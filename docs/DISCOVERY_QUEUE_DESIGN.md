# TASK-D-DISCOVERY-001：“今晚看什么”队列专项设计

> 状态：已实现
>
> 基线：`main@2aad85e0`，数据库运行格式保持 V18
>
> 依赖：现有 `WatchRecord`、媒体分类、兴趣等级、IMDb 评分、题材、平台、TMDB 状态和观看概览
>
> 不在第一版：跨重启队列、云端同步、自动修改观看状态、机器学习推荐、在看续播、长期永久屏蔽

实施结果：独立 discovery 纯函数已实现候选资格、单次时长、完结判断、组合筛选、100 分解释模型和稳定排序；Dashboard 已接入会话内浏览/跳过、准确空状态、估算标记及只读条目摘要。该功能不修改现有 `calculateWatchValue`，不调用写 IPC，也不新增 V18 或 WebDAV 状态。

## 1. 已确认决策

用户确认全部采用推荐方案：

1. 锁定条目继续参与推荐；锁定只保护业务写入，不代表用户不想观看。
2. “今晚看什么”只推荐 `未看` 条目；`在看` 继续由“正在观看”区域承载，二者不混合。
3. 电影按整部时长，剧集、综艺和分集内容按单集时长。
4. 第一版队列不跨重启保存，关闭观看概览后重新生成，不增加数据库或同步状态。
5. 第一版提供时长、媒体类型、平台和“仅已完结”筛选。
6. “换一个”在当前轮次不重复；候选全部浏览后由用户明确重新开始。
7. 提供“本轮跳过”；它只在当前观看概览会话有效，不修改条目。
8. 推荐卡片只提供“查看条目”“本轮跳过”“换一个”，不直接把记录改为“在看”。

## 2. 当前实现与问题

当前 `Dashboard.tsx` 已能从未看且未锁定记录中，按 30/60/120 分钟或不限时长过滤，再按 `calculateWatchValue` 排序并循环“换一个”。基础算法使用 IMDb 评分、兴趣倍率、完结加成，以及用户高分已看记录的题材/平台匹配。

当前缺口：

- 锁定被误用为推荐排除条件；
- “换一个”到末尾后无提示地回到第一项；
- 没有本轮跳过、媒体类型、平台和仅已完结筛选；
- 推荐只显示一个总分，无法解释各项原因；
- 缺失时长使用默认值却没有标为估算；
- `Miniseries` 的计分和展示完结语义不一致；
- 同分排序没有正式稳定契约；
- 推荐逻辑写在 Dashboard 组件内，缺少独立纯函数和边界测试；
- 记录在面板打开期间变成已看时，虽会重新计算候选，但没有目的明确的回归验收。

## 3. 候选资格

先按以下硬条件建立候选集：

1. `record.status === '未看'`；
2. 不检查 `isLocked`，锁定记录仍可进入候选；
3. 符合当前媒体类型筛选；
4. 符合当前平台筛选；
5. 符合“仅已完结”筛选；
6. 单次预计观看时长不超过当前时长上限；
7. 记录 ID 不在本轮显式跳过集合中。

任何时刻 records 更新都必须重新验证候选。条目变为 `在看`、`已看`、被删除或不再符合筛选时，立即从当前队列移除；不能因为它之前已被推荐而保留。

### 3.1 媒体类型

复用 `mediaTypeOf(record)`，选项为“全部”以及当前未看数据中实际存在的媒体类型。筛选项没有候选时保留当前选择并显示明确空状态，不偷偷回退为全部。

### 3.2 平台

平台选项来自当前未看候选记录的非空规范化 `platform`，按显示名称稳定排序。“全部”包含平台缺失记录；选择具体平台时，平台缺失记录不匹配。

### 3.3 已完结语义

- 电影和其他单部作品天然满足“仅已完结”；
- 分集内容仅在 `tmdbStatus` 为 `Ended` 或 `Miniseries` 时满足；
- 缺失或其他状态不推断为已完结。

## 4. 单次观看时长

推荐引擎返回时长数值和来源，界面不能把默认值伪装成精确元数据。

| 内容 | 时长来源 | 缺失时默认值 | 展示示例 |
| --- | --- | --- | --- |
| 电影/单部作品 | `movieDuration / 60`，向上取整 | 120 分钟 | `约 108 分钟` / `时长未知，按 120 分钟估算` |
| 剧集/综艺/分集内容 | `episodeRuntime` | 45 分钟 | `单集约 50 分钟` / `单集时长未知，按 45 分钟估算` |

只要 `totalEpisodes > 0`，即按分集内容处理；这样分集纪录片和动画不会误按单部时长。时长筛选按钮文案固定为“30 分钟内”“1 小时内”“2 小时内”“不限”。

## 5. 独立且可解释的推荐分数

新增 discovery 专用纯函数，不修改当前用于主列表排序的 `calculateWatchValue`，避免路线图任务意外改变现有“待看价值”排序。

第一版使用 100 分加法模型：

| 分项 | 分数 |
| --- | --- |
| 兴趣 1/2/3/4/5 | 0 / 14 / 28 / 38 / 50 |
| 兴趣缺失 | 28（中性） |
| IMDb | 有效 0～10 分乘以 3，最多 30；缺失按 18 分中性值 |
| 已完结 | 8 |
| 喜爱题材匹配 | 每个 4 分，最多两个、合计最多 8 |
| 常看平台匹配 | 4 |

喜爱样本继续定义为 `已看` 且用户个人评分不低于 8 分的记录。题材按规范化后的精确标签匹配，平台按规范化后的完整名称匹配，不做子串判断。总分限制在 0～100。

排序顺序固定为：推荐总分降序、兴趣等级降序、IMDb 评分降序、规范化标题升序、记录 ID 升序。不得使用当前时间、随机数或数据库返回顺序打破平局。

引擎同时返回结构化分项和最多三条主要理由，例如：

> 非常期待 · IMDb 8.7 · 已完结 · 与高分作品中的“科幻”题材匹配

缺失 IMDb、时长采用默认值等不是加分理由，但必须作为数据说明展示。

## 6. 队列与交互状态

全部状态只存在于本次 Dashboard 挂载期间：

- `filters`：时长、媒体类型、平台、仅已完结；
- `seenIds`：当前筛选组合下已经通过“换一个”浏览过的记录；
- `skippedIds`：用户明确点击“本轮跳过”的记录，在本次面板内跨筛选继续排除；
- `currentId`：当前推荐记录。

规则：

1. 打开面板或改变筛选条件时，从当前 records 重新生成稳定队列；改变筛选会清空 `seenIds`，但保留 `skippedIds`。
2. “换一个”把当前 ID 加入 `seenIds`，显示下一项；同一筛选轮次内不重复。
3. “本轮跳过”同时写入 `skippedIds` 和 `seenIds`，直到关闭面板前都不再出现。
4. 当前轮次候选耗尽时显示“本轮候选已看完”；“重新浏览”只清空 `seenIds`，仍保留显式跳过项。
5. 关闭并重新打开观看概览后，筛选恢复默认值，浏览和跳过集合全部清空。
6. records 变化后如果 `currentId` 已失效，自动选择重新计算后的第一项；这个过程不修改记录。

“查看条目”打开 Dashboard 内的只读条目摘要，不写数据库。锁定条目与普通条目使用相同只读能力。第一版不从推荐卡片直接打开编辑表单或改变状态。

## 7. 空状态

推荐引擎按资格阶段返回统计，界面显示最接近真实原因的固定文案：

- 没有未看记录：`暂无待看作品`；
- 只有时长不匹配：`没有符合当前时长的作品`；
- 类型不匹配：`没有符合当前类型的作品`；
- 平台不匹配：`没有符合当前平台的作品`；
- 仅已完结导致为空：`没有符合条件的已完结作品`；
- 全部被本轮跳过：`本轮候选已全部跳过`；
- 当前轮次浏览完：`本轮候选已看完`。

不得自动放宽筛选，也不得把已看或在看记录补进来填充空位。

## 8. 数据、同步与错误边界

第一版是纯读取、纯内存功能：

- 不增加 SQLite 表、列、setting 或功能 marker；
- 不调用 Rust 业务写命令；
- 不提升 records generation；
- 不写 staging/outbox，不触发自动同步；
- 不改变 V18、本地备份格式或 WebDAV V4；
- 算法异常或畸形元数据按保守默认值处理，不能阻断观看列表读取。

只有未来用户明确要求跨重启保存人工队列时，才另行设计目的限定 Rust 命令、导入导出和同步语义；不得把第一版内存队列直接写入通用 setting。

## 9. 实施拆分

1. 从 Dashboard 提取 discovery 纯函数：资格、时长、完结判断、分数分项、稳定排序、筛选统计。
2. 用队列 reducer 或等价的集中状态模型实现浏览、跳过、筛选重置和 records 变化处理。
3. 重构推荐卡片，增加筛选、解释理由、估算标记、空状态和只读详情。
4. 保持现有观看概览的统计、趋势、最近完成和常看题材不变。
5. 增加 Node 纯函数测试和 Playwright 交互测试，再执行完整前后端门禁。

## 10. 验收标准

1. 已看和在看记录永不进入新作品推荐；面板打开期间改变状态后立即退出。
2. 锁定记录可以被推荐，浏览和查看不会产生任何数据库写入。
3. 电影按整部时长、分集内容按单集时长；默认估算有明确标签。
4. `Ended`、`Miniseries` 和单部作品的完结筛选语义一致。
5. 四类筛选可以组合，并在无结果时给出准确原因。
6. 推荐分数、理由和稳定排序与纯函数结果完全一致。
7. “换一个”本轮不重复；“本轮跳过”跨筛选有效；重新浏览不恢复显式跳过项。
8. 关闭重开后没有遗留筛选、浏览、跳过或人工队列状态。
9. 查看、换一个、跳过和筛选均不调用写 IPC，不产生 outbox 或同步 PUT。
10. 原有观看概览统计与主列表“待看价值”排序保持不变。

## 11. 实施证据

本地完整门禁通过：Node 85/85、Playwright 63/63、Rust 72/72，以及 TypeScript typecheck、ESLint、生产构建、rustfmt 和 Clippy。专项测试覆盖锁定未看可推荐、在看/已看排除、电影/单集时长和默认估算、`Ended`/`Miniseries`、四类组合筛选、稳定分数与理由、本轮不重复、跳过跨筛选、关闭重置、只读摘要及零业务写 IPC。后续展示修订还覆盖中国大陆分集内容隐藏冗余“第一季 / Season 1”但保持原始数据不变，以及看板“正在观看”按媒体类型显示电影时间/百分比或剧集下一集。测试只使用纯函数夹具、临时 SQLite 和 mock IPC/WebDAV，未读取或写入正式便携数据库。
