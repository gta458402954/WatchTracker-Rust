# TASK-D-UX-003-R1：系列识别、完整季补充与归组体验重构

> 状态：已实现（2026-08-09）  
> 数据库主版本：继续使用 V18；使用独立功能迁移  
> 兼容目标：本地备份 V4、WebDAV payload V6

## 目标与边界

本修订把“发现一个条目属于什么系列”“补齐同一电视剧缺少的季”和“关联电影、衍生剧、特别篇”拆成三个明确动作。任何 TMDB 结果在用户确认前均为只读预览；补全只创建缺少条目，不覆盖已有条目。

默认不扫描整个片库。系统先使用本地稳定信息识别已知多季作品：已有 `tmdb:tv-show:<id>` 收藏集、持久化 TMDB 身份、同 IMDb 下可识别的不同季、明确季标记或用户确认。中文标题无法判断时，用户可选择“某一季 / 整部剧 / 单部作品 / 稍后处理”。

## 身份与收藏集模型

记录新增可空字段：`tmdbMediaKind`、`tmdbId`、`tmdbParentId`、`tmdbSeasonNumber`、`seriesRecordKind`。收藏集新增 `collectionKind` 与 `orderMode`。主数据库仍为 V18，通过 `tmdb_identity_schema_version=1` 和 `collections_schema_version=2` 幂等迁移；迁移前建立 `series-identity-migration` 恢复点。

锁定记录可参与识别与预览，但不会被自动写回 TMDB 身份。身份缓存是设备本地派生数据，不进入备份、WebDAV、revision、staging 或 outbox。

## 发现与缓存

请求优先级为：记录持久化身份、收藏集 `sourceKey`、同 IMDb 的本地结果、有效缓存、网络。相同 IMDb 在一次任务中只查询一次；最多 4 路并发，支持进度与取消。成功缓存 30 天，明确无结果缓存 7 天。

“发现系列”位于收藏集中心，用于处理本地候选；“检查缺失季”只对已确认的电视剧系列开放；“关联相关作品”由用户搜索并确认后加入 `universe` 收藏集，不自动猜测影视宇宙。

## 完整季预览与写入

TMDB 电视剧详情一次返回 `seasons`。预览中：已存在季禁用；已经播出的常规季默认勾选；第 0 季默认隐藏且不勾选；未来或日期未知季不勾选。提交前 Rust 再次按稳定 TMDB 身份检查重复。

新增季默认为“未看”，观看进度、评分、起止日期为空；标题、年份、集数、海报和可用元数据来自 TMDB。Rust 目的限定命令 `create_missing_seasons` 在一个事务中创建记录、收藏集成员、generation、staging 与 outbox；任何失败全部回滚，恢复点原因使用 `series-completion`。

## 排序与展示

收藏集成员显示为“标题 · 年代”，年代仅用于展示，不写入标题。`chronological` 模式按年份从老到新，未知年份最后，同年按季号、标题和 ID 稳定排序；第 0 季排在常规季之后。该模式隐藏上下移动按钮并提供“按年代重新排列”；`manual` 模式保留手工顺序。

Rust 批量加入必须保持调用方提供的记录顺序，禁止通过 `HashSet` 迭代破坏顺序。

## 编辑表单归组

“所属收藏集”移动到表单下部的“整理与归组”。主表单只展示最多两个已选收藏集和 `+N`；未加入时显示“尚未加入收藏集”。“管理”打开可搜索选择器，分为“已加入 / 建议加入 / 其他收藏集”，所有更改仍随保存记录一起提交。

## 交换格式与安全

完整本地备份升级为 V4，WebDAV payload 升级为 V6。V6 首次发布必须显式确认；V5 客户端遇到 V6 必须拒绝并保持零 PUT。身份缓存永不进入交换格式。所有预览、扫描和取消路径保持零业务写入。

## 验收

- 本地识别不产生网络请求；相同 IMDb 不重复请求；缓存 TTL 与取消行为可测试。
- 缺失季预览的默认选择、特别季、未来季、重复阻止正确。
- 原子批量创建故障时 records、members、generation、staging、outbox 全部不变。
- 年代显示和从老到新排序稳定，手工模式仍可移动。
- RecordForm 默认不再平铺所有收藏集，360 px 无横向溢出。
- V4/V6 往返无损，旧格式兼容与未来格式拒绝符合规则。
