# TASK-D-NET-001：网络响应与海报缓存安全专项设计

> 状态：IMPLEMENTED（2026-08-05）
>
> 设计日期：2026-08-05
>
> 数据边界：继续使用 V18；不改变本地备份格式或 WebDAV V4
>
> 范围：TMDB JSON、海报下载、WebDAV 响应限额，以及海报缓存的校验、原子落盘、并发和清理

实施结果：TMDB JSON、海报与 WebDAV 已使用独立响应/请求上限和超时；海报路径、MIME 与实际签名在 Rust 校验，通过同目录临时文件发布，并使用 4 路全局许可和单文件锁去重。海报墙及 TMDB 搜索缩略图不再由 WebView 直连 TMDB，CSP 已移除该权限；缺图通过安全命令下载，失败显示占位和手动重试。设置页提供缓存统计、未引用清理和二次确认的全部清空。自动容量回收只删除未引用文件，当前记录引用文件和未完成临时下载始终受到保护。数据库保持 V18，WebDAV 保持 V4。

## 1. 当前问题

当前 Rust 海报下载已经把最终文件限制在统一 `posters/` 目录的单个安全文件名内，但仍有以下缺口：

1. `download_poster` 使用 `Response::bytes()` 把完整响应一次性读入内存，没有 `Content-Length` 预检或流式硬上限。
2. 下载成功后直接 `File::create` 最终文件；断网、进程退出或写盘失败可能留下半个文件，已存在文件也只按“路径存在”判断为有效。
3. 只检查 HTTP 状态，不检查响应声明的 MIME 或实际文件签名。
4. 每次调用新建客户端，没有统一连接/请求超时、并发上限或同一路径请求合并。
5. 缓存没有容量统计、临时文件回收和未引用文件清理。
6. 海报墙在 `poster://` 失败后直接切到 `https://image.tmdb.org`，绕过 Rust 下载、代理、大小限制和缓存校验。
7. TMDB JSON 与 WebDAV GET/PROPFIND 也直接调用 `json()` / `text()`，同样缺少响应体上限；但二者的数据规模和兼容要求不同，不能套用海报限额。

海报缓存属于可重建的派生数据。数据库只保存 TMDB `posterPath`，缓存文件不进入 SQLite、恢复点、导入导出或 WebDAV，因此缓存清理不得修改记录或提升 generation/outbox。

## 2. 不变量

1. 任何网络失败、校验失败、容量不足或缓存清理都不得修改业务记录。
2. 未完整下载并通过校验的内容不得出现在最终缓存文件名下。
3. 一个有效的旧缓存文件不得因一次失败的刷新而被截断或覆盖。
4. 响应限制按端点类别独立配置；海报安全改动不得误伤 WebDAV 同步。
5. 所有持久文件写入继续由 Rust 完成；React 不接收原始响应体或本地绝对路径。
6. TMDB API Key、WebDAV 凭据、代理凭据和完整带查询 URL 不进入日志或前端错误通知。
7. 本任务不升级 V18，不改变 WebDAV V4，也不要求重建已有缓存。

## 3. 响应策略

### 3.1 统一有界读取器

Rust 增加可测试的流式有界读取器：

- 若 `Content-Length` 已存在且超过上限，请求体读取前立即拒绝；
- `Content-Length` 缺失或不可信时仍逐块计数，超过硬上限立即停止；
- 只保留上限以内的数据，不允许先完整分配再判断大小；
- 超限返回稳定错误码，不在错误中回显响应正文；
- 每类请求使用单独的连接超时、总超时、MIME 规则和上限。

推荐第一版参数：

| 请求类别 | 响应硬上限 | 连接超时 | 总超时 | 内容规则 |
| --- | ---: | ---: | ---: | --- |
| TMDB 搜索/详情 JSON | 4 MiB | 10 秒 | 30 秒 | 成功响应必须是 JSON MIME，随后再解析 |
| TMDB 海报 | 10 MiB | 10 秒 | 45 秒 | 仅 JPEG、PNG、WebP；声明与实际签名共同校验 |
| WebDAV GET 同步文件 | 64 MiB | 15 秒 | 120 秒 | 成功响应解析为 JSON；超限时保持本地不变 |
| WebDAV PROPFIND | 1 MiB | 15 秒 | 60 秒 | XML/文本，仅提取当前所需 ETag |
| WebDAV PUT 请求体 | 64 MiB 本地发送上限 | 15 秒 | 120 秒 | 发送前检查，超限不发起 PUT |

WebDAV 的状态码、强/弱 ETag、条件提交和重试语义保持不变。重定向策略也按服务分离：TMDB API/图片只允许固定 HTTPS 主机内的有限重定向；WebDAV 只允许 HTTPS 且禁止降级到 HTTP，跨主机重定向不得携带凭据。

## 4. 海报路径和内容校验

`posterPath` 继续保存 TMDB 路径，但下载入口增加严格语法校验：必须是 `/文件名.扩展名`，不得含 URL scheme、主机、查询串、反斜杠、嵌套目录或 `..`。允许扩展名为 `.jpg`、`.jpeg`、`.png`、`.webp`，文件名只接受 ASCII 字母、数字、`-` 和 `_`。

响应校验分两层：

1. 若服务明确返回非图片 MIME，立即拒绝；若 MIME 缺失或为 `application/octet-stream`，仍可进入实际签名校验，以兼容部分代理。
2. 下载完成后使用文件头识别实际格式，只接受 JPEG、PNG、WebP。实际格式不在白名单，或与明确的图片 MIME 冲突时拒绝。

最终 `poster://` 协议继续按实际字节推断响应 MIME，并增加最大文件大小和格式复检。旧缓存若无效，返回不可用状态，不把任意字节交给 WebView 解码。

## 5. 原子下载流程

每次海报请求采用以下流程：

1. 规范化并校验 TMDB 路径，计算最终文件名。
2. 获取全局下载许可，再获取该文件名的单文件锁；获取锁后重新检查缓存，避免等待期间重复下载。
3. 已存在文件只有通过大小与签名校验才算 `cache_hit`；无效文件不直接返回成功。
4. 在同一 `posters/` 目录用不可预测名称创建 `create_new` 临时文件，例如 `.poster-<uuid>.part`。
5. 流式写入临时文件并执行 10 MiB 硬限制；任何失败都关闭并删除临时文件。
6. 完成后校验实际格式，刷新缓冲并 `sync_all`。
7. 通过同目录原子替换把临时文件发布为最终文件。若另一进程已发布有效文件，则保留胜出的文件并删除本次临时文件。
8. 返回结构化结果：`cache_hit`、`downloaded` 或稳定失败码；不再只返回难以诊断的布尔值。

推荐全局最多同时进行 4 个海报下载，同一文件名最多 1 个。并发状态只存在于进程内，不写数据库。

## 6. 缓存生命周期

推荐使用无索引缓存，不新增数据库表：缓存统计和清理直接扫描 `posters/`，并从当前 records 生成被引用文件名集合。

第一版策略：

- 启动时自动删除超过 24 小时的 `.part` 临时文件；
- 缓存软上限 500 MiB，回收目标 400 MiB；
- 超过软上限时，按文件修改时间从旧到新删除未被任何记录引用的缓存；
- 自动清理永不删除当前记录仍引用的有效海报，即使引用文件总量超过 500 MiB；这种情况只报告“缓存超过建议容量”；
- 设置页显示有效缓存数、未引用数、无效/临时数和总容量；
- 提供“清理未引用缓存”和“清空全部海报缓存”两个显式操作。清空全部必须二次确认，但不创建数据库恢复点，因为记录数据不变且海报可重新下载。

删除条目或取消尚未保存的 TMDB 选择可能留下未引用海报；它们在容量压力或用户手动清理时回收。第一版不记录精确的“成为孤立文件时间”，避免为派生缓存增加持久索引。

## 7. 界面与失败语义

推荐取消海报墙当前的远端直连 fallback：

- 本地缓存存在时只使用 `poster://`；
- 缺失或无效时，由受限 Rust 命令尝试下载一次并刷新图片；
- 本轮下载失败则显示占位图和“重试海报”，不影响条目内容、保存或同步；
- 不无限自动重试，不因滚动重复产生请求风暴。

TMDB 搜索列表中的 `w92` 缩略图也推荐统一经过 Rust 的同一安全下载器，但使用独立缓存键和较小尺寸，不能与正式 `w342` 文件互相冒充。缩略图请求共享 4 路并发限制；组件卸载后不再更新 React 状态。实施完成后从 CSP 移除 WebView 对 `https://image.tmdb.org` 的直接图片访问权限，只保留 `poster:`。

用户可见提示保持简洁：元数据已保存但海报失败时，明确说明“条目数据不受影响”；详细原因只进入脱敏日志。稳定内部错误码至少包括：

- `poster_path_invalid`
- `poster_response_too_large`
- `poster_content_type_invalid`
- `poster_signature_invalid`
- `poster_timeout`
- `poster_cache_write_failed`
- `tmdb_response_too_large`
- `webdav_response_too_large`

## 8. 模块拆分

建议将 `net.rs` 中不同职责拆开，但不借本任务重构整个同步层：

- `net/limits.rs`：流式有界读取、超时和响应 MIME 辅助函数；
- `poster_cache.rs`：路径规范化、文件校验、临时文件、原子发布、并发与清理；
- 现有 `net.rs`：TMDB/WebDAV 请求编排，调用共享有界读取器；
- `commands.rs`：目的限定 IPC，返回脱敏结构化结果；
- React：缓存状态、单次重试和设置页维护入口。

是否拆成目录模块可按实际代码量调整；行为测试先于机械拆分。

## 9. 测试与验收

所有网络测试只连接本机 mock server，所有文件测试只使用临时目录，不访问真实 TMDB、WebDAV、用户数据库或正式便携目录。

Rust 测试至少覆盖：

1. 有/无 `Content-Length` 的正常响应和流式超限；
2. 404、超时、截断响应、非图片 MIME、错误签名和允许格式；
3. 非法 TMDB 路径、跨主机/HTTP 重定向拒绝；
4. 下载失败不产生最终文件，刷新失败保留旧有效文件；
5. 同文件并发合并、全局 4 路上限和锁后缓存复检；
6. 旧有效缓存命中、旧无效缓存替换、残留 `.part` 清理；
7. 500 MiB 策略下只回收未引用文件，引用文件和 records 不变；
8. TMDB JSON、WebDAV GET/PROPFIND/PUT 分别使用自己的上限；
9. 日志与错误中不包含 API Key、WebDAV 密码、代理凭据或响应正文。

Node/Playwright 测试至少覆盖：

1. 本地海报缺失时只触发一次安全下载，成功后切回 `poster://`；
2. 下载失败显示占位和可控重试，条目仍可保存且不产生业务写入；
3. 搜索缩略图不再直接使用 `https://image.tmdb.org`；
4. 设置页缓存统计、未引用清理、全部清空确认和失败提示；
5. CSP 不再允许 WebView 直连 TMDB 图片主机；
6. 现有同步成功、条件冲突、超限失败本地不覆盖的回归测试。

完整门禁为 typecheck、lint、Node tests、Playwright、前端生产 build、Rust tests、rustfmt 和严格 Clippy。只有全部通过并确认活动数据库哈希未变化后，才允许提交并按既有流程打包便携版。

## 10. 实施顺序

1. 先建立响应限额、路径、签名、临时文件和缓存清理的 Rust 单测。
2. 实现共享有界读取器和端点独立策略，保持 WebDAV 条件提交行为不变。
3. 实现海报原子缓存、并发控制、结构化结果和协议复检。
4. 修改海报墙与搜索缩略图，删除 WebView 远端 fallback 并收紧 CSP。
5. 增加设置页缓存统计与显式清理。
6. 完成全门禁、真实用户数据只读哈希核对、Git 提交，再构建和部署便携版。

## 11. 已确认产品决策

用户于 2026-08-05 确认采用以下三项推荐方案：

1. 采用 500 MiB 软上限、400 MiB 回收目标；自动清理只删除临时文件和未引用文件，绝不自动删除仍被记录引用的海报。
2. 取消海报墙远端直连 fallback；安全下载失败时显示占位图和手动重试，条目数据照常保留。
3. TMDB 搜索结果缩略图也经过 Rust 安全下载，并在实施后从 CSP 移除 `image.tmdb.org` 直连权限。
