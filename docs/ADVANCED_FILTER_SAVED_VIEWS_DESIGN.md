# TASK-D-UX-001：高级筛选与保存视图专项设计

> 状态：IMPLEMENTED
> 日期：2026-08-09
> 推荐范围：统一筛选模型、高级筛选面板、本机保存视图；不修改 records、V18 schema 或 WebDAV payload

## 1. 当前实现与问题

当前主列表已有五类筛选/排序入口，但状态分散在 `App.tsx`：

- 顶部搜索：中文名、原名、平台、备注的文本包含匹配。
- 媒体类型：单选。
- 观看状态：单选。
- 地区：单选，且严格沿用“只读取每条记录第一个国家代码”的现行规则。
- 锁定状态：全部、已锁定、未锁定三态。
- 排序：最新添加、完成时间、上映年份、个人评分、待看价值。
- 显示模式：列表或海报墙。

现有 `filterRecords` 已能安全组合这些条件，但没有统一的查询对象，不能表达多选、范围条件，也不能保存和恢复一组条件。地区选项目前只按媒体类型与观看状态计算作用域；搜索和锁定状态不影响地区选项计数，这是已经测试锁定的行为。

## 2. 产品原则

1. 保留现在的顶部媒体类型、状态、地区和搜索入口，常用操作不增加步骤。
2. “高级筛选”是结构化表单，不实现任意 AND/OR 嵌套的规则编辑器。
3. 同一字段内多选使用 OR；不同字段之间使用 AND。
4. 保存视图只保存查询与展示方式，不保存结果记录 ID 或动态计数。
5. 筛选永远只读 records；保存/重命名/删除视图只写本机设置，不触发 records generation、outbox 或 WebDAV 同步。
6. 无效条件不得被静默丢弃并扩大结果范围；必须可见地显示为“当前无匹配值”。

## 3. 推荐界面

### 3.1 顶部快捷入口

- 搜索框右侧增加“筛选”按钮，显示已启用的筛选维度数量，例如“筛选 4”。
- 原有媒体类型、状态、地区按钮保留。点击它们仍是快捷单选：
  - 点击某项会把该字段替换为单个值；
  - 再次点击当前单值会恢复“全部”；
  - 高级面板中存在多个值时，顶部不伪装成某个单选值，改为显示“多选 2”摘要。
- 锁定三态按钮保持现状，但状态并入统一查询模型。
- 增加“清除筛选”，只清空查询条件，不改变排序和列表/海报墙模式。

### 3.2 高级筛选面板

推荐使用从顶部展开的响应式面板：桌面端为搜索区下方的浮层，窄屏为全宽弹层。字段分为：

| 分组 | 条件 | 规则 |
| --- | --- | --- |
| 基础 | 媒体类型 | 电影、剧集、纪录片、综艺、动画；多选 OR |
| 基础 | 观看状态 | 在看、未看、已看；多选 OR |
| 基础 | 地区 | 动态国家代码，包含“未知地区”；多选 OR；仍只匹配条目第一个国家 |
| 来源 | 平台 | 从现有记录动态聚合；大小写和首尾空格规范化后精确匹配 |
| 内容 | 题材 | 从 `genres` 逗号分隔值动态聚合；多选 OR |
| 内容 | 内容标签 | 从 `contentTags` 动态聚合；多选 OR；不把旧地区回退值重复展示成普通标签 |
| 评分 | 个人评分 | 可选最小值、最大值，范围 0–10；缺失评分不匹配启用的范围 |
| 评分 | IMDb 评分 | 可选最小值、最大值，范围 0–10；缺失评分不匹配启用的范围 |
| 年份 | 上映年份 | 可选起止年份；无法解析的旧年份在启用范围时不匹配 |
| 状态 | 锁定 | 全部、已锁定、未锁定 |

第一版不加入任意字段表达式、正则、NOT、嵌套条件、日期范围、时长范围和“字段是否缺失”。这些能力会显著增加解释、失效迁移和测试成本，可根据实际使用再扩展。

### 3.3 条件摘要与空状态

- 面板关闭后，在内容区顶部显示可逐个移除的条件标签，例如“剧集或综艺”“地区：中国大陆、英国”“个人评分 ≥ 8”。
- 搜索文字单独显示，不计入面板字段标签，但计入“筛选维度数量”。
- 无结果时显示“当前筛选没有匹配记录”，并提供“清除全部条件”和“修改筛选”；不得显示“还没有记录”或添加第一条记录按钮。
- 总记录数为零时仍使用现有真正空库提示。

## 4. 统一查询模型

建议新增纯前端模型：

```ts
interface WatchlistQueryV1 {
  schemaVersion: 1;
  searchText: string;
  mediaTypes: MediaType[];
  statuses: Status[];
  regions: RegionFilterValue[];
  platforms: string[];
  genres: string[];
  contentTags: string[];
  lock: 'all' | 'locked' | 'unlocked';
  releaseYear: { min: number | null; max: number | null };
  rating: { min: number | null; max: number | null };
  imdbRating: { min: number | null; max: number | null };
}
```

- 空数组表示该维度“全部”，不另外保存 `all` 哨兵。
- 所有输入经过 trim、去重、稳定排序和范围校验，保证同一查询能稳定比较。
- 查询比较采用规范化后的深比较，用于判断保存视图是否被临时修改。
- 排序和显示模式属于视图展示配置，不进入 `filterRecords`：

```ts
interface SavedWatchlistViewV1 {
  id: string;
  name: string;
  query: WatchlistQueryV1;
  sortBy: SortBy;
  viewMode: 'list' | 'poster';
  createdAt: string;
  updatedAt: string;
}
```

## 5. 保存视图

### 5.1 基础行为

- 提供不可删除的内置“全部记录”，等价于空查询、最新添加和列表模式。
- 用户最多保存 20 个视图；名称 trim 后为 1–30 个字符，忽略大小写后不可重复。
- 保存内容包括搜索文字、全部筛选条件、排序和列表/海报墙模式。
- 选择保存视图后，界面一次性应用完整快照。
- 修改已选择视图的任一条件、排序或显示模式后，显示“视图名 · 已修改”，不自动覆盖。
- “更新当前视图”需要明确点击；“另存为”创建新 ID。
- 删除当前视图后保留当前筛选结果并转为“临时筛选”，避免页面突然跳回全部记录。

### 5.2 启动行为（推荐）

- 默认每次启动进入“全部记录”，避免旧筛选导致用户误以为数据丢失。
- 可对一个保存视图启用“设为启动视图”；只有用户明确设置后才在启动时恢复。
- 启动视图被删除、损坏或版本不兼容时回退“全部记录”，显示一次非阻塞提示。

### 5.3 持久化边界（推荐）

- 使用现有 SQLite `settings` 表保存 `watchlist_saved_views_v1` 与 `watchlist_startup_view_id_v1`，不新增表、不升级 V18。
- 视图只属于当前设备：不进入本地 records 导入导出、WebDAV payload、同步合并或恢复点业务统计。
- 写设置失败时保留当前内存状态但明确提示“视图未保存”；不得假装保存成功。
- JSON 根对象带 `schemaVersion: 1`。读取失败或未知未来版本时不覆盖原值，只回退内置视图并记录安全日志。

## 6. 动态值和失效策略

- 平台、题材、标签、地区候选值从当前 records 聚合，只用于提供选择，不决定已保存条件是否合法。
- 保存视图引用的值后来从 records 消失时，仍保留条件并标记“当前无匹配值”；结果可以为零，用户可手动移除。
- 已知枚举值在未来被删除或重命名时，通过版本化解析器显式迁移；无法识别的枚举条件使该视图进入“需要修正”，不能静默放宽查询。
- 地区继续调用现有国家规范化逻辑，`UK` 等别名归一为 `GB`，“未知地区”哨兵保持可保存。
- 恢复点或云端同步替换 records 后重新计算候选项，但不修改保存视图。

## 7. 状态与组件边界

- `App.tsx` 用一个 `WatchlistQueryV1` 替换现有五个分散筛选 state；不引入 Zustand。
- `filtering.ts` 保持纯函数，新增查询规范化、匹配、聚合和活动维度计数。
- 新增 `useSavedWatchlistViews`，只负责读取、校验和写入现有 settings 命令。
- 新增 `AdvancedFilterPanel` 与 `SavedViewBar`；`Header` 和 `StatsBar` 只接收统一查询的派生值及更新回调。
- 排序函数从 `App.tsx` 提取为纯函数，便于保存视图与单元测试复用。

## 8. 可访问性与窄屏

- 高级面板具有明确名称；窄屏弹层复用 `useAccessibleDialog`，支持焦点陷阱、Escape 和焦点恢复。
- 多选组使用可访问名称和 `aria-pressed`/原生复选框；范围输入关联可见标签与错误说明。
- 已保存视图使用按钮或标签页语义，不用仅靠颜色表达选中/已修改状态。
- 360 px 宽度不横向溢出；条件标签允许换行，操作按钮保持可达。

## 10. 已确认决策

用户于 2026-08-09 确认全部采用推荐方案：

1. 第一版按推荐字段范围实施，不加入日期、时长、缺失字段和 NOT 条件。
2. 同字段多选统一采用 OR，不增加“全部匹配”切换。
3. 保存视图只保存在本机，不跟随 WebDAV 同步。
4. 默认进入“全部记录”，允许用户手工设定一个启动视图；不恢复最后一次临时筛选。
5. 保存视图包含搜索文字、排序和列表/海报墙模式。

## 11. 实施结果

- `App.tsx` 已改用统一 `WatchlistQueryV1`，顶部快捷筛选与高级面板共享同一查询状态；未引入 Zustand。
- 高级面板已覆盖媒体类型、观看状态、第一国家地区、平台、题材、内容标签、年份、个人/IMDb 评分与锁定状态，并提供活动条件摘要、逐项移除和准确空状态。
- 保存视图支持另存为、明确更新、临时修改提示、删除后保留条件、最多 20 个、本机启动视图以及损坏/未来版本安全回退。
- 视图只写现有 settings 键，不升级 V18、不写 records、不产生 outbox、不进入 WebDAV；数据库兼容检查失败时不会提前读取任何 setting。
- 消失或未来枚举条件会保留为不匹配条件，不会因静默删除而扩大结果范围；动态地区仍只使用条目第一个国家。
- 2026-08-09 验收通过：Node 100/100、Playwright 72/72、Rust 75/75，以及 typecheck、lint、生产 build、rustfmt 和严格 Clippy。
